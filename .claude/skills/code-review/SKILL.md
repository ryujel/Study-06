# Code Review

코드를 5개 항목(버그/오류, 보안 취약점, 코드 품질, 성능, 유지보수성) 기준으로 분석하고,
이슈를 CRITICAL / WARNING / INFO 3단계로 분류해 파일 경로·라인 번호·구체적인 수정 코드와 함께 보고하는 스킬이다.

## 사용법

| 명령 | 설명 |
|---|---|
| `/code-review` | git diff 기반 변경사항 리뷰 (작업 트리의 unstaged + staged 변경사항) |
| `/code-review src/app.ts` | 특정 파일 리뷰 |
| `/code-review --staged` | 스테이징된 변경사항만 리뷰 |
| `/code-review --full` | 프로젝트 주요 파일 전체 리뷰 |

인자는 `args`로 전달된다. 아래 규칙으로 스코프를 판단한다:

1. **인자 없음** → `git diff HEAD` (unstaged + staged 변경사항)을 대상으로 한다. git 저장소가 아니면 그렇게 안내하고 중단한다.
2. **`--staged`** → `git diff --staged`만 대상으로 한다.
3. **`--full`** → 변경사항이 아니라 프로젝트의 주요 소스 파일 전체를 대상으로 한다. `node_modules`, `dist`, `build`, `.git`, 바이너리/락파일 등은 제외하고, 실제 애플리케이션 코드(예: `src/`, `lib/`, `app/` 등)를 우선한다. 파일이 매우 많으면 핵심 파일부터 순서대로 리뷰하고 있음을 밝힌다.
4. **파일/디렉토리 경로가 주어짐** → 해당 파일(들)만 대상으로 한다. Read로 전체 내용을 읽고 리뷰한다.

리뷰 대상이 없으면(diff가 비어 있는 등) 그 사실을 그대로 보고하고 종료한다. 이슈를 지어내지 않는다.

## 분석 항목

- **버그 및 오류** — 로직 오류, null/undefined 참조, 예외 처리 누락, 비동기 처리 누락(unhandled promise, race condition 등), 경계값 오류
- **보안 취약점** — SQL 인젝션, XSS, 하드코딩된 시크릿/API 키/자격증명, 안전하지 않은 역직렬화, 인증/인가 우회, 입력값 미검증 등 (OWASP Top 10 기준)
- **코드 품질** — 중복 코드, 과도한 복잡도(깊은 중첩, 긴 함수), 네이밍 불일치, 죽은 코드
- **성능** — N+1 쿼리, 불필요한 반복 연산, 비효율적인 알고리즘/자료구조 선택
- **유지보수성** — 높은 결합도, 낮은 응집도, 테스트하기 어려운 구조(하드코딩된 의존성 등)

## 이슈 분류 기준

- **CRITICAL** — 보안 취약점, 실제 런타임 오류/데이터 손상/인증 우회로 이어지는 버그. 반드시 수정 필요.
- **WARNING** — 잠재적 버그, 성능 저하, 심각한 유지보수성 문제. 수정을 권장.
- **INFO** — 스타일, 사소한 개선, 선택적 권장사항.

## 절차

1. 대상 코드를 실제로 읽는다 (`git diff` 출력 또는 Read로 파일 원문). 추측으로 이슈를 만들지 않는다.
2. 위 5개 항목 기준으로 코드를 분석한다.
3. 발견한 각 이슈마다 다음을 포함해 기록한다:
   - 심각도(CRITICAL/WARNING/INFO)
   - 파일 경로 (`file:line` 형식, 클릭 가능하게)
   - 문제 설명 (한두 문장, 구체적인 실패 시나리오 포함)
   - 수정 코드 (원본과 비교되는 코드 블록 또는 diff 형태로, 실제 적용 가능한 수준으로 작성)
4. 이슈가 없는 항목은 생략하고, 발견된 이슈만 심각도 순(CRITICAL → WARNING → INFO)으로 나열한다.
5. 마지막에 요약을 붙인다: 총 이슈 수(심각도별 개수), 리뷰 대상 범위, 한줄 총평.

## 출력 형식 예시

```
## 코드 리뷰 결과 (대상: git diff, 3개 파일)

### 🔴 CRITICAL (1)
**src/auth/login.ts:42** — 사용자 입력값을 검증 없이 SQL 쿼리에 직접 삽입해 SQL 인젝션에 노출됨.
수정 코드:
\`\`\`ts
// Before
const query = `SELECT * FROM users WHERE email = '${email}'`;
// After
const query = 'SELECT * FROM users WHERE email = ?';
db.query(query, [email]);
\`\`\`

### 🟡 WARNING (1)
**src/api/orders.ts:18** — 반복문 안에서 매번 DB 조회를 수행해 N+1 쿼리 발생.
...

### ⚪ INFO (1)
**src/utils/format.ts:5** — 변수명 `d`가 의미를 알 수 없음. `date`로 변경 권장.

---
**요약**: CRITICAL 1건, WARNING 1건, INFO 1건 (총 3건) · 대상: git diff 기준 3개 파일
```

## 주의사항

- 실제로 파일을 읽거나 diff를 확인하지 않고 이슈를 만들어내지 않는다.
- 라인 번호는 실제 파일 내용과 정확히 일치해야 한다.
- 리뷰만 수행하고, 사용자가 명시적으로 수정을 요청하지 않는 한 코드를 직접 고치지 않는다.
